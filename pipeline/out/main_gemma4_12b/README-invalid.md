Полный прогон Gemma 4 12B (6000 строк) снят на Kaggle-ядре `odinodinodin/hs-gemma4-12b`
(2026-11-01, пин `d4cff114c`), технически прошёл целиком, но **модель отвечала

## Почему непригоден: модель не отвечает на вопрос

Среди «чистых» (не обрезанных) строк доминируют ответы-заглушки, повторяющие
формулировку инструкции:

| ответ | строк |
|---|---|
| `The answer is the answer.` | 880 |
| `The correct answer is **C**.` | 598 |
| `The correct answer is the first option.` | 312 |
| `The correct answer is **A**.` | 147 |
| `The answer is the answer, no explanation.` | 86 |
| `The correct answer is the one that states the correct answer.` | 67 |

Обрезанные строки — те же шаблоны, ушедшие в цикл (`The correct answer is **C**.` ×N,
229+160 строк), либо утечка служебных маркеров в текст
(`<|channel>thought <channel|><|channel>th…` — 316 строк, `<|channel> <|channel> …` — 56),
либо схлопывание слова (`I've've've've…`). Средняя длина ответа у обрезанных — 276.6
символа против 41.9 у чистых; среднее число токенов 104.5 против 49.8.

Доля деградаций по сплитам одинаковая (train 0.382 / val 0.387 / test 0.382), то есть
это не отдельный «трудный» кусок данных, а свойство всего прогона.

## Чем это не объясняется (проверено)

- **Не промпт и не шаблон**: шаблон из GGUF совпадает с официальным
  `google/gemma-4-12B-it/chat_template.jinja` (различия только в обработке tool-call),
  инструмент рендерит канонический Gemma 4-промпт, `template: true` в `config.json`.
- **Не VRAM и не квант как таковой**: та же схема на E4B (Q4_K_M, локально) и на 26B-A4B
  даёт нормальные ответы; пилот 40 строк на 12B воспроизвёл ту же деградацию.
- **Не «слабое семейство»**: E4B на тех же входах размечен нормально (0.383 по
  `filtered_b`), см. `pipeline/out/main_gemma4e4b`.

## Что здесь оставлено и зачем

- `meta.jsonl` (6000 строк, 11 МБ) — сгенерированные ответы, `logprobs`, `entropies`;
  это единственный след деградации.
- `hidden_a.npy`, `hidden_c.npy` — по 2.1 ГБ, посчитаны корректно, но состояния сняты
  с модели, которая не отвечает по существу; в анализ не идут.
- `labels.csv` — честная разметка этих ответов (9 правильных).
- `config.json`, `verify.json` — параметры прогона и проверка целостности.

Каталог оставлен как свидетельство; не удалять. Пилот того же прогона —
`pipeline/out/pilot_gemma4_12b` (те же деградации). Диагностика причины — в
`kaggle/gemma4_12b_debug/` и в `report.md`; для анализа 12B нужен новый прогон в
отдельном каталоге (`main_gemma4_12b_*`), после того как модель начнёт отвечать.
