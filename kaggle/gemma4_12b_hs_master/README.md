# Ядро-гейт: наш `hs` на master (gemma-4-12B)

Ядро `odinodinodin/hs-gemma4-12b-master-gate`, `NvidiaTeslaT4`. Собирает в одной GPU-сессии
клон master, кладёт в него наш `hidden-states.cpp` из датасета `odinodinodin/hs-src`,
качает `gemma-4-12b-it-Q4_K_M.gguf` и проверяет адекватность ответов: 8 простых вопросов
(ожидание 8/8) и пилот 200 строк (ожидание: нет мета-текста, нет `truncated` пачкой).
Только `--layers 0`, чтобы массивы оставались крошечными: прогон про ответы и скорость.

## v1 (2026-11-01, 33.5 мин, 0.56 ч квоты): порт компилируется, ответы — мусор

Сборка `BUILD DONE in 1518.4s`, rc=0. Ответы:

| прогон | результат |
|---|---|

Примеры: `The provided text is a summary of a larger work.` · `It appears that the context of
your previous message is missing from this current view.` · `<|channel>thought<channel|>` × N.
Для сравнения, тот же вопрос на том же master через `llama-completion` — `William Shakespeare`.

Вывод v1: **версия llama.cpp — не единственная причина**. Даже на master наш инструмент
ломает 12B, значит он подаёт модели не тот промпт/не те токены, что `llama-cli`.

## Причина: промпт без ведущего `<bos>`

`llama.cpp` при рендеринге чат-шаблона **вырезает** ведущий BOS-текст из результата и ждёт,
что его вернёт токенизатор (`common/chat.cpp`: `if (inputs.add_bos &&
string_starts_with(result, tmpl.bos_token())) result = result.substr(...)`).
`llama-completion` так и делает: `common_tokenize(ctx, prompt, true, true)` —
`add_special=true` (`tools/completion/completion.cpp:279`).

Наш пакетный режим токенизировал шаблонный промпт с `add_special=false`
(`hidden-states.cpp:1561`, `no_template ? add_bos : false`), то есть BOS терялся.
У `gemma-4-12B`: `tokenizer.ggml.add_bos_token = True`, `bos_token_id = 2`.

Проверено на самом GGUF (`vocab_only`, веса не грузятся):

| | значение |
|---|---|
| отрендеренный промпт | 132 символа, начинается с `<|turn>user`, `<bos>` нет (вырезан llama.cpp) |
| `add_special=false` (как было) | 27 токенов, первый `105` = `<|turn>` |
| `add_special=true` (как в `llama-cli`) | **28 токенов, первый `2` = `<bos>`** |

Одиночный режим (v1) всегда использовал `add_bos` (`hidden-states.cpp:1777`), поэтому
расхождение «пакетный vs одиночный» проверками не ловилось: они сравнивались на
`--no-template`, где обе ветки брали `add_bos`.

## Попутно: `suppress_tokens` больше не действуют в графе

`tokenizer.ggml.suppress_tokens` у 12B — `[258882, 258883]` = `<image|>`, `<audio|>`.
До 2026-07-29 llama.cpp применял их внутри графа; коммит `afeebe103` («move suppress_tokens
handling to common/sampling») перенёс это в цепочку сэмплера и добавил
`llama_vocab_get_suppress_tokens`. Наш greedy-argmax сэмплера не имеет, поэтому на master
эти токены стали доступны для выбора. Теперь они пропускаются явно (под тем же
`#if __has_include("json.h")`, что и остальной порт).

## Правки в `hidden-states.cpp`

1. токенизация шаблонного промпта с `add_bos` (как `llama-cli`), а не с `false`;
2. жадный выбор токена идёт через общий `hs_argmax`, который пропускает подавленные
   моделью токены (только когда API есть).

Оба изменения касаются только пакетного режима и только пути с шаблоном; одиночный режим
(v1) и `--no-template` не меняются.

## Какие модели это затрагивало (проверено по GGUF, без загрузки весов)

Механизм включается, только если у модели `tokenizer.ggml.add_bos_token = true` **и** шаблон
печатает `{{ bos_token }}`: llama.cpp ставит `inputs.add_bos = llama_vocab_get_add_bos()`
(`common/chat.cpp`, и на пине, и на master), поэтому сам вырезает `<bos>` из результата
рендеринга и ждёт его от токенизатора. Если шаблон BOS не печатает, вырезать нечего, но
`add_special=false` всё равно не добавит его — так было с nemotron_h.

`hs-prompt-dump` (vocab_only, веса не грузятся) на локальных GGUF:

| модель | `add_bos` | BOS в шаблоне | промпт после рендера | `add_special=false` | `add_special=true` |
|---|---|---|---|---|---|
| gemma-4-E2B / E4B / 12B / 26B | true | да | без `<bos>` | первый токен `105` `<\|turn>` | первый токен `2` `<bos>` |
| nemotron_h 4B | true | нет | без `<bos>` | первый токен `10` | первый токен `1` |
| LFM2.5-1.2B Instruct/Thinking | true | да (`{{- bos_token -}}`) | без `<bos>` | первый токен `6` | первый токен `1` |
| Qwen3.5 (0.8B…9B) | false | нет | без `<bos>` | 28 токенов | **те же 28** — не меняется |
| gpt-oss-20b | false | нет | без `<bos>` | 82 токена | **те же 82** — не меняется |

Значит правка `add_bos` **не влияет** на серию Qwen 3.5 и gpt-oss (их артефакты
воспроизводятся новым бинарником байт-в-байт), но меняет промпт для трёх уже прогнанных
моделей: **Gemma 4 E2B (`out\main_gemma4e2b`), Gemma 4 E4B (`out\main_gemma4e4b`),
Nemotron 3 Nano 4B (`out\main_nemotron3nano4b_v2`)**.

Что с ними: ответы были осмысленными (strict 0.168 / 0.389 / 0.295), пробы прошли контроли,
то есть отсутствие BOS у этих моделей к мусору не приводило (в отличие от 12B, где тот же
дефект дал 0.002 strict). Артефакты остаются действительными, но это измерения на промпте
**без ведущего `<bos>`**, а не на том, что подаёт `llama-cli`. Отсюда:

- числа трёх прогонов **не пересчитывать и не удалять** — они заморожены;
- при сравнении с новыми прогонами тех же моделей помнить, что промпт отличается на один
  токен; прямой перенос `probe_model.npz` при этом возможен (признак — вектор слоя C);
- если понадобится эталон «как `llama-cli`», E4B перегоняется новым бинарником в **новый**
  каталог (`out\main_gemma4e4b_bos`) — ~20 мин на 3050.

`suppress_tokens` есть только у 12B (`[258882, 258883]` = `<image|>`, `<audio|>`); у остальных
локальных GGUF ключа нет. Пин (`d4cff114c`) ещё применяет их в графе, так что на старых
прогонах правка тоже ничего не меняет.
